# 統合デザインルール / 実装仕様 2.0

対象は受領した86枚。SUMMARY.mdに画像ごとの要約を保存し、本書では重複を統合して実装に対応付ける。以下の具体的なサイズ・上限・色コード・検査閾値は本の指定ではなく、本プログラムの設計値である。

## 適用前の確認

新規制作・全体のデザイン改訂では、[DESIGN_BRIEF.md](DESIGN_BRIEF.md) に沿ってユーザーのデザイン希望を確認してから制作する。本書の単色面・少数色などは基礎となる設計と同梱HTMLの制約であり、合意したポップな表現、イラスト、写真、強調やページ間の抑揚を排除しない。生成器で表現できない場合は対応する作成手段を使い、未実装の機能があるとは説明しない。

## 1. 内容と構造を先に決める
1ページに主題と要旨を置く。情報を選別し、図解で意味・条件・根拠を失わない。比較は同じ軸・順番、フローは実際の順序、階層は全体と部分を表す。循環を因果と混同しない。入力JSONに書かれていない数値・実績・関係を生成器は追加しない。

実装：13種類のtypeを限定。因果フロー・因果循環・グラフには出典を要求。ただし出典文字列の存在は内容の正しさを証明しない。意味の確認は人が担当する。

## 2. 余白・整列・近接・強弱・反復
外周、ブロック間、囲み内部に別の余白を設定する。同じ階層の要素は同じ幅・書式で揃える。見出しと本文は近く、異なるまとまりは離す。余白と配置を土台にし、情報のまとまりを見分ける必要があれば枠や背景面も使う。見出しと説明を同じ領域にまとめ、装飾の少なさだけを優先して構造を曖昧にしない。提案資料・説明スライドの表現選択は [VISUAL_STRUCTURE.md](VISUAL_STRUCTURE.md) を参照する。

実装：1280×720、左右64px、上54px、本文24px、見出し34px、表紙64px、注記14px。本文行間1.5。複数列の間隔と箱の内側余白を共通CSSで固定。文章は左揃え、表の数値は右揃え。本文に不必要な番号や中黒を追加しない。手順の番号は意味のある識別として認める。

見出し・本文・補足で書式を分け、全文太字にしない。文字の自動縮小、内容の自動削除は行わない。上限を超える場合は短文化・ページ分割が必要。文字数上限内でも長い単語や特定の組み合わせで収まらない場合があり、表示検査も併用する。

## 3. 図形と矢印
箱は四角・単色面、影・立体・グラデーション・大きな角丸は使わない。矢印は細い線または控えめな方向記号。同列の形・大きさ・位置を揃える。基本は左から右、上から下。Z/N型の説明を万人の眼球運動の保証とは解釈しない。

実装：flow、cycle、hierarchy。階層は親と子の1段に限定し、深い階層は複数ページへ分解する。任意のネットワーク図、包含図、吹き出しやベクター編集ソフトの操作は対象外。AIの任意SVG・CSS・アイコン指定は受け付けない。

## 4. 色と文字
背景・本文・補足・強調の役割を固定。役割が違っても同じ色を兼用できる。色数を使い切ろうとしない。写真の主要色との調和を考える。本文は黒に近い灰色を基本にし、薄くしすぎない。

実装：neutral / mono / red / oliveの4テーマ。全テーマの本文・補足・強調色について、背景・面との相対輝度コントラスト比4.5以上を検査する。これは今回の設計基準であり、資料全体のアクセシビリティ適合認定ではない。主役を増やすための自由色指定を禁止する。フォントは同梱のNoto Sans JPをHTML内に埋め込み、外部通信なしで利用する。

コントラスト検査は色覚シミュレーションではない。投影の明るさ、印刷紙、眩しさ、個人による見え方、写真との調和は実物で確認する。写真からの色の自動抽出や、色覚特性別のシミュレーションは実装対象外。

## 5. グラフ
正確な値は表、項目比較は棒、推移は線、構成比は円、2変数の関係は散布図。過剰な補助線や枠・3Dは使わない。単位・出典を保持する。凡例を別の場所で照合させず、ラベルを対象に近づける。

実装：棒はゼロを含む数値軸、負値も表示、任意の対称誤差バー。線は最大3系列で直接ラベル・線種・記号を併用。円は正の値から割合を計算して外側に直接ラベルを置く。小数第1位への丸めで合計が100.0にならない場合がある。散布図は点ラベルと両軸名を表示し、回帰線を勝手に追加しない。全グラフに読む表示用の元データ表を併記する。

重なりや範囲外ラベルはブラウザで検査する。線とラベルの意味上の対応や、点同士の重なりは人が確認する。複合軸、ドーナツ、積み上げ、対数軸、回帰分析、非対称誤差バーは対象外。必要な場合は表や別ページを使い、分析上必要な表現を勝手に代替・削除しない。

## 6. 表
見出しと本文を区別し、縦罫線を増やさない。数値は右、文章は左上へ揃える。セル余白を確保し、任意で控えめな交互行背景を使う。

実装：最大5列6行。JSONの数値型の列は自動右揃え、明示的なalignも可能。数値はPythonで読み込んだ値を表示し、グラフの目盛りのみ短く丸める。末尾のゼロや厳密な小数点桁を保持したい値は文字列で渡しalignをrightにする。元データ以上の精度を示すゼロ埋めはしない。小数点位置を揃える機能は未搭載。

## 7. 画像・キャプション・注釈
原画像を変更せず、縦横比を保持。キャプションを画像の近くへ置く。説明は図の外側を基本とし、必要な対象を番号で対応させる。証拠となる情報を切り抜いたり消したりしない。

実装：PNG/JPEG/WebPを入力、EXIF回転を適用、全体を枠内に収める。原ファイルは維持し、HTMLには表示用PNGまたはJPEGを埋め込む。代替テキスト・キャプション必須。注釈は相対座標と外側説明で最大3件。小さい画像は警告。印刷用300ppiの一律保証や自動トリミング、背景除去、袋文字、自由な引き出し線は搭載しない。透過を持つ画像はPNGとして保持する。

## 8. 出力と確認
HTMLは16:9スライド表示と一段組の読む表示を切り替え可能。狭い画面は読む表示で開く。長文はリフローし、図の数値は元データ表で読める。印刷はスライド表示に切り替える。自動アニメーションは使わない。

生成時は入力形式、値の範囲、必須出典、テーマの明暗差を検証する。開いたブラウザでは実フォントを使い、領域外の文章・図ラベル・ラベル同士の重なりを検査し、エラー時は印刷を止める。検査はすべての重なり・意味・美しさの保証ではない。最終確認項目：事実、因果、比較条件、自然な文章、読み順、改行、画像の意味と鮮明さ、投影・印刷の見え方。
